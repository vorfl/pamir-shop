# PAMIR — магазин в Telegram (Mini App)

Витрина — статический сайт на GitHub Pages (`/webapp`). Бэкенд — Google Apps Script, привязанный к таблице «PAMIR — Товари» (`/apps-script`). Сервера и платных сервисов нет.

**Сейчас готовы этапы 1–5:** каталог, корзина и оформление, приём заказов с уведомлениями админам, открытие магазина из бота, админ-панель (заказы, товары, фото, категории, настройки).

В репозитории нет и не должно быть токена бота. Токен хранится только в Script Properties (см. «Этап 3» ниже).

## Что где лежит

| Файл | Зачем |
|---|---|
| `apps-script/Code.gs` | Код бэкенда. Вставляется в Apps Script таблицы |
| `apps-script/appsscript.json` | Настройки проекта Apps Script (часовой пояс Киева). Необязательно |
| `webapp/index.html`, `styles.css`, `app.js` | Витрина |
| `webapp/config.js` | Единственный файл, который вы правите руками: URL бэкенда |
| `webapp/demo-catalog.json` | 8 демо-товаров. Показываются, пока в `config.js` пусто |

## Шаг 1. Бэкенд: вставить код в таблицу

1. Откройте таблицу «PAMIR — Товари» → меню **Расширения → Apps Script**. Откроется редактор кода в новой вкладке.
2. Слева файл `Код.gs` (или `Code.gs`). Удалите в нём всё, вставьте содержимое `apps-script/Code.gs` целиком. Нажмите значок дискеты (**Сохранить**).
3. Вверху, в выпадающем списке функций, выберите **testCatalog** → кнопка **Выполнить**.
4. Первый запуск попросит доступ: **Проверить разрешения** → ваш аккаунт → «Google не проверял это приложение» → **Дополнительные настройки** → **Перейти на страницу … (небезопасно)** → **Разрешить**. Это нормально: скрипт ваш собственный и работает только с этой таблицей.
5. Внизу в «Журнале выполнения» должно появиться: `Товарів у каталозі: 303`, размер ответа и первый товар.

## Шаг 2. Бэкенд: опубликовать как веб-приложение

1. В редакторе справа вверху: **Начать развертывание → Новое развертывание**.
2. Шестерёнка рядом с «Выберите тип» → **Веб-приложение**.
3. «Запуск от имени»: **Я**. «У кого есть доступ»: **Все**. → **Начать развертывание**.
4. Скопируйте **URL веб-приложения** (заканчивается на `/exec`).
5. Проверка: вставьте этот URL в адресную строку браузера и допишите в конец `?action=catalog`. Должен открыться текст, начинающийся с `{"ok":true,...` со списком товаров.

> Важно на будущее: когда код в `Code.gs` меняется, нужно **Начать развертывание → Управление развертываниями → карандаш → Версия: Новая версия → Начать развертывание**. URL при этом остаётся прежним. Если создать «Новое развертывание», URL изменится и его придётся заново вставлять в `config.js`.

## Шаг 3. Витрина: GitHub Pages

1. Зарегистрируйтесь на https://github.com (если аккаунта нет).
2. Справа вверху **+ → New repository**. Имя: `pamir-shop`, тип **Public**, галочка **Add a README file** не нужна → **Create repository**.
3. На странице репозитория ссылка **uploading an existing file**. Распакуйте архив `pamir-shop.zip` и перетащите в окно браузера **содержимое** папки (папки `webapp`, `apps-script` и файл `README.md`) → внизу **Commit changes**.
4. **Settings → Pages** (в левом меню). «Source»: **Deploy from a branch**. «Branch»: **main**, папка **/ (root)** → **Save**.
5. Через 1–2 минуты витрина откроется по адресу `https://ВАШ_ЛОГИН.github.io/pamir-shop/webapp/` — пока с демо-товарами и синей полосой сверху.

## Шаг 4. Соединить витрину с таблицей

1. В репозитории откройте `webapp/config.js` → значок карандаша (**Edit**).
2. Вставьте URL из шага 2 между кавычками: `API_URL: 'https://script.google.com/macros/s/.../exec'` → **Commit changes**.
3. Подождите 1–2 минуты и обновите страницу витрины. Синяя полоса про демо исчезнет, появятся товары из таблицы.

## Что проверить после этапа 1

Откройте `https://ВАШ_ЛОГИН.github.io/pamir-shop/webapp/?debug=1` на телефоне и на компьютере.

- [ ] Видны все 4 категории и товары из таблицы, поиск находит «курага» и «кеш'ю».
- [ ] Курага DRY-039 (380 ₴/кг): на карточке `38 ₴ за 100 г`; в шторке 250 г = `95 ₴`, 500 г × 2 шт = `380 ₴`.
- [ ] Поставьте у любого товара в таблице «немає» → в таблице меню **PAMIR → Оновити каталог у магазині зараз** → обновите витрину: товар серый, внизу списка, кнопка «Немає в наявності» не нажимается. (Без меню изменение появится само не позже чем через 5 минут.)
- [ ] Измените цену за 1 кг → то же самое: новая цена на витрине.
- [ ] Переключатель UA / RU меняет названия и кнопки.
- [ ] Тёмная тема: добавьте в адрес `&theme=dark`.
- [ ] На телефоне нет горизонтальной прокрутки страницы (лента категорий листается вбок — так и задумано).
- [ ] В ответе `...?action=catalog` нет слов «Конкурент», «Закупка», «Маржа», ссылок на do-smaku.

Меню **PAMIR → Перевірити каталог** в таблице показывает, сколько товаров увидит клиент и у каких нет цены или фасовки. Меню появляется после перезагрузки вкладки с таблицей.

## Как устроен ответ каталога

`GET <API_URL>?action=catalog` → `{ ok, updated, shop, categories[], products[] }`.

Товар: `id`, `c` (код категории), `ua` / `ru` (название), `t` (`w` весовой, `p` упаковка, `u` штука), `a` (1 — можно заказать), `img`, `dUa` / `dRu`, `w` / `wm` (опт).
Весовой: `k` — цена за 1 кг, `v` — варианты `[граммы, цена]`, цена = `round(k × граммы / 1000)`.
Упаковка / шт: `p` — цена, `pk` — подпись фасовки.

Колонки ищутся по названию заголовка. В ответ попадают только поля из белого списка `PRODUCT_COLS` в `Code.gs`; служебные колонки скрипт не читает.

## Фото товаров

В колонку «Фото (посилання)» подходит ссылка Google Drive вида `https://drive.google.com/file/d/.../view` — скрипт сам превратит её в прямую. У файла должен быть доступ «Все, у кого есть ссылка». Ссылки на сообщения Telegram как картинки не работают.

# Этап 3. Заказы и уведомления

После этого этапа заказ из витрины записывается в лист «Замовлення», админ получает сообщение в Telegram с кнопками, клиент получает статус.

## Шаг 1. Обновить код бэкенда

1. Таблица «PAMIR — Товари» → **Расширения → Apps Script**.
2. В файле `Код.gs` удалите всё и вставьте новое содержимое `apps-script/Code.gs` целиком → **Сохранить** (дискета).

## Шаг 2. Свойства скрипта (здесь живёт токен)

1. В редакторе слева значок шестерёнки **Настройки проекта**.
2. Внизу раздел **Свойства скрипта** → **Изменить свойства скрипта** → **Добавить свойство скрипта**. Добавьте три строки:

| Свойство | Значение |
|---|---|
| `BOT_TOKEN` | токен @pamir_spices_bot из BotFather |
| `WEBAPP_URL` | `https://vorfl.github.io/pamir-shop/webapp/` |
| `ALLOW_TEST_ORDERS` | `1` |

3. **Сохранить свойства скрипта**.

`ALLOW_TEST_ORDERS = 1` разрешает тестовые заказы из обычного браузера (`?debug=1`). **Перед тем как показывать магазин клиентам, удалите это свойство**: без него сервер принимает заказы только из Telegram.

## Шаг 3. Включить бота

1. Вернитесь в редактор (значок `< >` слева). В списке функций вверху выберите **startPolling** → **Выполнить**.
2. Скрипт попросит новые разрешения (подключение к внешнему сервису и запуск по расписанию): **Проверить разрешения** → аккаунт → **Дополнительные настройки** → **Перейти на страницу…** → **Разрешить**.
3. В журнале внизу: `Готово. Бот @pamir_spices_bot опрашивается раз в минуту`. В таблице появится лист «Замовлення».

## Шаг 4. Узнать chat id админа

1. С аккаунта админа (@gladiroon) откройте @pamir_spices_bot, нажмите **Start** и отправьте `/id`.
2. В течение минуты бот ответит: `Ваш chat id: 123456789`.
3. **Настройки проекта → Свойства скрипта** → добавьте `ADMIN_CHAT_IDS` = это число. Несколько админов: числа через запятую, каждый админ должен сам нажать Start у бота.
4. В редакторе выберите функцию **testBot** → **Выполнить**. Админу придёт «PAMIR: перевірка зв'язку ✅», а в журнале будет видно, всё ли настроено.

## Шаг 5. Обновить развёртывание

**Начать развертывание → Управление развертываниями → карандаш → Версия: Новая версия → Начать развертывание.** URL остаётся прежним. Без этого шага витрина продолжит работать со старым кодом и заказ не отправится.

## Что проверить после этапа 3

Откройте `https://vorfl.github.io/pamir-shop/webapp/?debug=1`.

- [ ] Соберите корзину, оформите заказ. На экране «Замовлення P-0001 прийнято».
- [ ] В листе «Замовлення» новая строка: статус `новий`, в колонке «Джерело» стоит `miniapp test`, сумма совпадает.
- [ ] Админу пришло сообщение с пометкой «ТЕСТ» и четырьмя кнопками.
- [ ] Нажмите **✅ Підтвердити**. В течение минуты статус в таблице сменится на `підтверджено`, а сообщение обновится.
- [ ] Поменяйте в таблице цену товара из корзины, не обновляя витрину, и оформите заказ: витрина вернёт в корзину с сообщением, что цены изменились.
- [ ] Напишите боту любое сообщение с другого аккаунта: придёт приветствие с кнопкой «Відкрити магазин».

Клиенту на тестовые заказы бот не пишет. Настоящие сообщения клиенту (заказ принят, подтверждён, отправлен) проверяются на этапе 4, когда магазин открывается из Telegram.

## Как это устроено

- Витрина отправляет на сервер только список товаров (ID, фасовка, количество) и данные формы. Цены сервер считает сам по таблице. Если сумма не совпала с той, что видел клиент, заказ не принимается, а витрина показывает свежую корзину.
- Сервер проверяет подпись Telegram (`initData`). Заказ с поддельной или просроченной (старше 24 часов) подписью отклоняется.
- Не больше 5 заказов в час с одного Telegram-аккаунта.
- Кнопки под заказом работают только у тех, чей chat id есть в `ADMIN_CHAT_IDS`. Задержка до минуты: бот опрашивается раз в минуту.
- Последняя колонка листа «Замовлення» («Службове») скрыта. В ней номера сообщений админам, чтобы обновлять их при смене статуса. Не удаляйте её.
- Статус можно менять и руками в таблице, но тогда клиент сообщение не получит.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| «Не вдалося надіслати замовлення» | Не обновлено развёртывание (шаг 5) или нет `BOT_TOKEN` |
| «Тестові замовлення вимкнені» | Нет свойства `ALLOW_TEST_ORDERS = 1` |
| Заказ в таблице есть, сообщения админу нет | Запустите `testBot`: в журнале будет причина. Обычно админ не нажал Start или неверный `ADMIN_CHAT_IDS` |
| Бот не отвечает на `/id` дольше 2 минут | Запустите `startPolling` ещё раз. Журнал запусков: слева значок **Выполнения** |
| Кнопки под заказом не меняют статус | То же: проверьте **Выполнения**, функция `pollUpdates` должна запускаться каждую минуту без ошибок |

# Этап 4. Магазин открывается из бота

## Шаг 1. Обновить код и запустить setup

1. Таблица → **Расширения → Apps Script**. В `Код.gs` удалите всё, вставьте новый `apps-script/Code.gs` целиком → **Сохранить**.
2. В списке функций выберите **setup** → **Выполнить**.
3. В журнале семь строк «готово» и в конце `Всё готово`. Если где-то `ОШИБКА`, пришлите эту строку.
4. Закройте чат с ботом и откройте заново: слева от поля ввода появится кнопка **Магазин**.

Обновлять развёртывание на этом этапе не обязательно: `setup` запускается из редактора, а код приёма заказов не менялся.

## Шаг 2. Прямая ссылка на магазин (BotFather)

Нужна для Instagram, визиток и постов: по ней магазин открывается сразу, без чата.

1. В Telegram откройте **@BotFather** → отправьте `/newapp`.
2. Выберите **@pamir_spices_bot**.
3. Название: `PAMIR`.
4. Описание: `Горіхи, сухофрукти та східні солодощі. Центральний ринок, Харків`.
5. Фото 640×360: отправьте файл `pamir-miniapp-640x360.png` из корня репозитория (как фото, не как файл).
6. GIF: отправьте `/empty`.
7. URL: `https://vorfl.github.io/pamir-shop/webapp/`
8. Короткое имя: `shop`.

BotFather ответит ссылкой `https://t.me/pamir_spices_bot/shop`. Это и есть прямая ссылка на магазин.

- [ ] После добавления товара внизу появляется большая оранжевая кнопка Telegram «Оформити замовлення · сума».

# Этап 5 (часть 1). Админ-панель: заказы и товары

Админ-панель живёт в том же Mini App. Отдельного пароля нет: сервер пускает только тех, чей Telegram id есть в `ADMIN_CHAT_IDS`, и проверяет это при каждом действии. В обычном браузере (в том числе с `?debug=1`) панель не открывается.

## Как включить

1. Вставьте новый `apps-script/Code.gs` в Apps Script → **Сохранить**.
2. **Управление развертываниями → карандаш → Новая версия → Начать развертывание.** На этом этапе обязательно: без новой версии панель покажет «Не вдалося завантажити».
3. Запустите **setup** ещё раз: у админов в меню команд бота появится `/admin`.

## Как пользоваться

- Админ отправляет боту `/admin` → кнопка **Відкрити адмін-панель**. После первого входа в шапке витрины появляется значок планшета, панель открывается и через него.
- **Замовлення:** последние 100 заказов, итоги за сегодня и за 7 дней, фильтр по статусу, поиск по номеру, телефону или имени. Нажатие на заказ раскрывает состав и кнопки статуса. Смена статуса срабатывает сразу (без минутной задержки), клиент получает сообщение, сообщения админов в Telegram обновляются.
- **Товари:** поиск по названию или ID, переключатель наличия в одно касание. Нажатие на название открывает правку: названия, цена, фасовки, описания.
- Всё пишется в ту же таблицу, поэтому править можно и в панели, и в таблице. На витрине правка из панели видна сразу.

В итоги не попадают тестовые заказы и заказы со статусом «немає в наявності».

# Этап 5 (часть 2). Новые товары, фото, категории, настройки

## Как включить

Делайте три шага подряд, без пауз: пока не выдан новый доступ (шаг 2), бот не отвечает на кнопки и сообщения.

1. Вставьте новый `apps-script/Code.gs` в Apps Script → **Сохранить**.
2. Выберите функцию **setupPhotos** → **Выполнить**. Google попросит доступ к Google Drive: в окне нажмите **«Выбрать все»** → **Продолжить**. В журнале появится ссылка на папку «PAMIR — фото товарів».
3. **Управление развертываниями → карандаш → Новая версия → Начать развертывание.**

## Что появилось в панели

## Этап 6 (часть 1): бейджи, «Наша курага», ссылка на товар

### Что появилось

- **Бейджи «Новинка / Хіт / Знижка».** Выбираются в карточке товара в админ-панели (поле «Бейдж на картці»). В таблице это колонка «Бейдж»: она создаётся сама при первом сохранении, писать можно словами «новинка», «хіт», «знижка».
- **Старая цена.** Поле «Стара ціна» в карточке товара (колонка «Стара ціна» в таблице). Пишется в тех же единицах, что и цена: за 1 кг у весового товара, за упаковку у остальных. На витрине она зачёркнута рядом с новой. Если старая цена задана, а бейдж не выбран, товар сам получает бейдж «Знижка». Старая цена ниже текущей не показывается. На сумму заказа она не влияет: сервер считает по текущей цене.
- **Блок наверху каталога («Наша курага»).** Настраивается во вкладке «Налаштування»: ID товара, заголовок и текст на двух языках. Пока ID пустой, блока нет. Блок виден на главном экране без поиска и фильтра и только пока товар в наличии.
- **Ссылка на товар для постов.** В карточке товара в админ-панели, внизу: поле со ссылкой и кнопка «Скопіювати посилання». Ссылка вида `https://t.me/pamir_spices_bot?start=DRY-039`: клиент попадает в чат бота и получает кнопку «Відкрити товар».

### Что сделать

1. Вставить новый `apps-script/Code.gs` в Apps Script, сохранить.
2. Управление развертываниями → карандаш → «Новая версия» → Начать развертывание.
3. В админ-панели: «Налаштування» → в поле «Блок угорі каталогу: ID товару» вписать ID кураги (например `DRY-039`) → «Зберегти».

Новых разрешений Google не попросит.

### Прямая ссылка без чата (по желанию)

После `/newapp` в BotFather (короткое имя `shop`) впишите в `webapp/config.js` строку `APP: 'shop'`. Тогда ссылки станут вида `https://t.me/pamir_spices_bot/shop?startapp=DRY-039` и будут открывать товар сразу, без сообщения в чате.

### Проверка

- Поставить товару бейдж «Хіт» и старую цену выше текущей: на карточке бейдж и зачёркнутая цена.
- Вписать ID кураги в настройки: блок появился над каталогом, нажатие открывает товар.
- Скопировать ссылку на товар, открыть её в Telegram: бот прислал кнопку, кнопка открыла магазин на этом товаре.
