# PAMIR — правила для Claude Code

Telegram Mini App магазина семьи на Центральном рынке Харькова (две точки):
орехи, сухофрукты, специи. Главный товар — курага и урюк из семейного сада в
Исфаре. Владелец онлайн-части — Исломбек, не программист: всё, что он делает
руками, описывать по шагам, по-русски, без жаргона.

## Устройство
- webapp/ — витрина на GitHub Pages (чистый JS без сборки).
- apps-script/Code.gs — бэкенд, Google Apps Script у таблицы «PAMIR — Товари».
  Таблица — единственное хранилище.
- worker/worker.js — Cloudflare Worker: webhook Telegram → Apps Script.
- Бот @pamir_spices_bot, Mini App t.me/pamir_spices_bot/shop, товар `?startapp=ID`.
- docs/ — планы и отчёты этапов. Задание текущего этапа — docs/STAGE9_PROMPT.md.

## Правила, которые нельзя нарушать
1. Цены и суммы считает сервер по таблице. Подпись initData проверяется.
   Запись в таблицу — под LockService.
2. Служебные колонки (закупка, маржа, конкурент, R–X) и Script Properties
   (токены, ключи, реквизиты) не уходят на витрину, в ответы API и в логи.
3. Ничего не выдумывать: остатки, «хит», отзывы, таймеры, свойства и состав
   товара. Нет данных — блок скрыт.
4. Подарки не меняют сумму. Скидки — только по решению владельца.
5. Секреты только в Script Properties и переменных Cloudflare.
6. Колонки — по названию заголовка. Новые колонки и настройки необязательные.
7. Права админов проверяет сервер при каждом действии.
8. Новая витрина работает со старым бэкендом.
9. startPolling() не вызывать никогда (удаляет webhook).
10. Каждый выпуск — своя ветка. В main не сливать: это делает Исломбек.

## Интерфейс
UA по умолчанию, RU по language_code; все тексты в i18n. Кнопки ≥ 44 px,
360 px без горизонтальной прокрутки, светлая и тёмная тема, без эмодзи в UI.
Цены «1 250 ₴». Нажатие сразу даёт отклик, серверные кнопки блокируются.

## Агенты (иерархия)
Главный агент (основная сессия) — руководитель: планирует, делит работу,
принимает решения, собирает результат, пишет отчёт. Сам большой код не пишет.
- pamir-explorer (Haiku) — разведка: где что лежит. Звать перед правками.
- pamir-backend (Sonnet) — Code.gs и тесты бэкенда.
- pamir-frontend (Sonnet) — webapp/ и e2e.
- pamir-worker (Sonnet) — Cloudflare Worker.
- pamir-tester (Sonnet) — прогон тестов, скриншоты, путь покупателя.
- pamir-security (Opus) — аудит безопасности, только чтение.
- pamir-reviewer (Opus) — независимая приёмка перед отчётом, только чтение.
Порядок блока работы: explorer → план главного → backend и frontend
параллельно → tester → исправления → reviewer → отчёт.
Если подключены агенты ECC — их можно звать в дополнение (например, второй
взгляд на безопасность), но правила этого файла важнее правил ECC.

## Проверка
- node tests/test_backend.js
- node tests/e2e.js (пути к Playwright и Chrome — в README или переменных среды)
Тесты расширять, не заменять. Перед отчётом смотреть скриншоты глазами.

## Выпуск (для отчёта Исломбеку)
Новый Code.gs → Deploy → Manage deployments → карандаш → New version → Deploy
(без этого работает старая версия) → Script Properties, если новые → пункты
меню PAMIR в таблице → только потом слить ветку в main.
