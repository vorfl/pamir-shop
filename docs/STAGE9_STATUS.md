## Решения
- Аудит запущен обычным агентом на Opus по тексту pamir-security.md: на тот
  момент агент pamir-security не загружался (ошибка YAML, исправлена позже).
- Полоска: новые настройки `notice_text_ua/ru` важнее старых `notice_ua/ru`,
  старые продолжают работать. Тексты запуска записывает пункт меню этапа 9 и
  только один раз: после очистки настройки повторный запуск полоску не вернёт.
- Закрытие полоски запоминается по тексту: новый текст покажется снова.
- Файлы фото не переименовываются под новые ID: ID новых товаров выбираются в
  таблице в момент запуска пункта меню, а в колонку «Фото» пишется полный
  адрес файла. NEW-*.webp остаются с прежними именами.
- Товар найден только в «Архів товарів» → строка не создаётся, в итоге пункта
  меню — подсказка восстановить через панель.
- Цены кураги не даны → у новых строк цена DRY-039; заполненную цену пункт
  меню не меняет.
- Старое подменю «Підготовка до запуску → Застосувати» делает специи весовыми
  и противоречит этапу 9: после пункта меню этапа 9 его не запускать.
- Реквизиты ФОП уходят отдельным сообщением после подтверждения заказа; на
  витрину отдаётся только флаг `shop.fop`. Назначение платежа всегда
  по-украински. Обещание «реквізити надішлемо» убирается только у заказов,
  которым реквизиты реально отправлены (отметка `r` в служебных данных).
- Кэш отделений Новой почты — 6 часов (предел CacheService), не 24.
  Лимит вызовов API НП снижен с 1500 до 600 в час (В4 из аудита).
- Узнавание «того же товара» под SPS-021…025 и DRY-089/090 — по ключевому
  слову в названии; иначе новый ID. При переводе в баночки очищаются старая
  цена, акция, опт и остаток (только при первой смене типа).
- «Наявність» у новых скрытых товаров не ставится: наличие не выдумываем.
- Пометка админу «⭐ Перше замовлення» со значком: сообщения админам в Telegram
  уже оформлены значками, правило «без эмодзи» относится к витрине.
- Функцию setup() не трогаем: при `USE_WEBHOOK` ≠ `true` она вызывает
  startPolling(). Не запускать её.
