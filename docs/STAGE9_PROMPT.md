Запуск: `Выполни задание из docs/STAGE9_PROMPT.md. Начни с аудита.`

Работаешь в репозитории vorfl/pamir-shop (Telegram Mini App магазина PAMIR).
Перед началом прочитай README, docs/ и правила проекта (скилл pamir-shop-dev,
если он есть; иначе docs/). Магазин запускается завтра, 19.11.2026. Работа в
два выпуска: А — к запуску сегодня, Б — после запуска. Делаешь выпуск А до
конца, с отчётом. Выпуск Б начинаешь, только когда я напишу «Делай выпуск Б».

<агенты>
Ты — главный агент: план, решения, сборка частей, финальная проверка, отчёт.
Работу раздавай агентам разного уровня, чтобы не тратить дорогую модель на
простое:
- поиск и чтение кода и docs — встроенный Explore или агент с model: haiku,
  только чтение;
- написание кода и тестов — агенты с model: sonnet. Бэкенд (apps-script/) и
  витрину (webapp/) можно делать параллельно: файлы не пересекаются;
- проверка перед отчётом — отдельный агент с model: opus, который этот код не
  писал. Проверяет правила из <правила>, безопасность и что старые данные не
  сломаны. Его замечания исправить до отчёта.
В начале создай в ветке файлы агентов для будущих сессий:
.claude/agents/pamir-explorer.md (model: haiku, tools: Read, Grep, Glob),
.claude/agents/pamir-builder.md (model: sonnet),
.claude/agents/pamir-reviewer.md (model: opus, только чтение и запуск тестов).
В описании каждого — когда его звать и правила проекта коротко.
Если в этой сессии подключены агенты и скиллы ECC (everything-claude-code),
сначала посмотри их список. Подходящие (планировщик, ревьюер кода, проверка
безопасности, e2e-тесты) используй вместо своих и не создавай дублей. Правила
проекта и этого промпта важнее правил ECC: ветки, запрет слияния в main,
существующие тесты и стиль кода не менять под ECC.
</агенты>
