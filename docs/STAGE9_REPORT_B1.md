**Надёжность перед рекламой (б7).**
- Каталог через Cloudflare Worker (кэш 60 с, сброс из меню и панели); Worker
  недоступен — витрина сама идёт в Apps Script.
- Быстрый режим: события и отметки клиентов копятся и пишутся раз в минуту
  короткими порциями, заказ их не ждёт. Включается пунктом меню.
- Заказ не теряется: при сбое корзина и форма остаются, повтор не создаёт второй
  заказ, в том числе после перезагрузки.
- Слежение: Worker раз в 5 минут проверяет магазин, после двух ошибок пишет
  админам «Магазин не відповідає», после восстановления — «Магазин знову працює».
- Копия таблицы раз в неделю в папку Google Drive, хранится 8 последних.
- Ошибки витрины уходят на сервер без личных данных; раз в час админам сводка
  «Помилки у магазині: N».
- Нагрузка — на стенде, см. раздел 2.

**Пункт б14 (добавлен 18.11).** Кнопка «Не нагадувати місяць» ставит напоминания
о корзине на паузу на `cart_mute_days` дней (по умолчанию 30) вместо «навсегда»;
бот отвечает строкой с датой. Старая отметка «так» остаётся «навсегда». В
статистике — сколько напоминаний отправлено и сколько человек их выключили за
30 дней (счёт с момента обновления).

### Где решил сам и почему
- Источник заказа пишется в новую колонку **«Джерело клієнта»**: «Джерело» в
  «Замовлення» уже занята, по ней определяется тестовый заказ.
- Учитываются только метки из настройки `src_list` (по умолчанию
  `qr1,qr2,insert`), чтобы посторонние не засоряли статистику. Для блогера —
  дописать его метку в список.
- «Сьогодні» — блок вверху первой вкладки, а не отдельная вкладка.
- Числа «Сьогодні» видны по правам (заказы — «статуси», товары — наличие, цена,
  фото).
- Новогодний блок и лента подарков показываются только при теме `newyear`; в
  ленте — только товары в наличии.
- Подпись к подарку дописывается в ячейку «Коментар» и идёт админу отдельной
  строкой.
- Сброс кэша Worker защищён уже существующим `WEBHOOK_SECRET` — новый секрет не
  нужен. Сбрасывают только меню и панель, не заказ.
- Сохранение корзины на сервере осталось под общей блокировкой с заказом:
  перевод в буфер мог бы вернуть корзину после заказа. Решение за Исломбеком.
- В сводке ошибок админы видят только тексты известного вида (сетевые и «тип @
  файл:строка»), остальное числом — иначе посторонний мог бы прислать свой текст.
- Комментарий к заказу хранится на телефоне до успешной отправки.
- Значки в превью статуса оставлены: это дословный текст сообщения клиенту.

**Аудит безопасности, два прохода.** Критичное найдено одно и исправлено: заказ
записан, ответ не дошёл, покупатель добавил товар и нажал «ещё раз» — добавленное
молча терялось. Теперь сервер сверяет состав; при другом составе покупатель видит
«Попереднє замовлення P-… уже прийняте…» и корзина сохраняется. Закрыты также:
чужой текст в сводке ошибок, малая ёмкость буфера событий, ожидание Worker
внутри заказа, обход лимита сообщений клиентам, папка копий по имени, токен бота
в журнале при сбое связи (В6 из выпуска А).

**Приёмка: принято с замечаниями, замечания исправлены.** Ревьюер нашёл:
вводящий в заблуждение текст при повторе заказа (мог привести к двойному
заказу); панель ломалась, если забыть файл `Stage9b.gs`; запись событий могла
надолго занимать блокировку заказов; у 20 настроек не было пояснений; выдуманный
ник в примере. После исправлений повторной приёмки не было — проверено тестами.

**Не проверено:**
- настоящий Telegram и телефон, настоящая таблица, настоящий Cloudflare (cron, KV);
- быстрый режим на живой таблице: стенд не показывает настоящую очередь Google,
  длительность записи и поведение блокировок;
- время открытия на реальной сети;
- качество новых фото на телефоне (проверены размер, формат и два снимка глазами);
- остаточный риск: при обрыве ровно между записью событий и сдвигом указателя
  строки аналитики могут задвоиться (заказов не касается).

## 3. Выпуск по шагам

Порядок безопасен в обе стороны: новая витрина работает со старым бэкендом.

1. **Код Apps Script.** Таблица → Расширения → Apps Script:
   - `Code.gs`, `Launch.gs`, `Stage9.gs` — заменить целиком файлами из ветки;
   - **новый файл:** «+» → Script → имя `Stage9b` → вставить
     `apps-script/Stage9b.gs`. Без него нет новых пунктов меню, копий, быстрого
     режима и сводки ошибок (остальное работает по-старому).
2. **Deploy** → Manage deployments → карандаш → Version: New version → Deploy.
   Без этого работает старая версия.
3. Обновить страницу таблицы → **«PAMIR → Етап 9Б: створити колонки»**. Сделать
   до печати QR: без колонок источник молча не записывается.
4. **«PAMIR → Увімкнути щотижневу копію»**, затем один раз «Зробити копію
   зараз» (Google попросит доступ к Диску — разрешить) и проверить, что на Диске
   появилась папка «PAMIR — резервні копії».
5. Проверить, что включён пункт **«Увімкнути щоденні повідомлення клієнтам»**:
   от его часового запуска зависит сводка ошибок.
6. **Слить ветку `stage9b1` в `main`.** Витрина и новые фото обновятся за 1–2 минуты.
7. **Cloudflare** (подробно — `worker/README.md`):
   - Workers & Pages → `pamir-bot` → Edit code → вставить `worker/worker.js` → Deploy;
   - Settings → Variables and secrets: `BOT_TOKEN` и `ADMIN_CHAT_IDS` (тип
     Secret) — вводите сами;
   - Cron Trigger `*/5 * * * *`;
   - хранилище KV с привязкой `PAMIR_KV` — без него слежение может молчать, а
     кэш каталога живёт недолго. [ЗАГЛУШКА: названия пунктов панели Cloudflare
     проверить на месте]
   - проверка: открыть `<адрес Worker>/catalog` — длинный текст с `"ok":true`.
8. **Script Properties:** добавить `WORKER_URL` = адрес Worker
   (`https://….workers.dev`, без `/catalog`). Другие адреса не принимаются.
9. **`webapp/config.js`** на GitHub → карандаш → строка `CATALOG_URL: ''` →
   вписать между кавычками `<адрес Worker>/catalog` → Commit. Без этого витрина
   Worker не использует. Делать после проверки из шага 7.
10. **Быстрый режим** — перед рекламой, не раньше: «PAMIR → Увімкнути швидкий
    режим», открыть магазин с телефона, через 2 минуты проверить, что в листе
    «Події» появились новые строки, а в Apps Script → Выполнения у `flushJob` нет
    ошибок и слов «втрачено», «буфер недоступний». Нет строк — «Вимкнути швидкий
    режим».

Не нажимать: функцию `setup()` и «Підготовка до запуску → Застосувати».

## 5. Что заполнить самому

В панели → «Налаштування» (или лист «Налаштування»):
- **Новый год:** `theme` = `newyear`, `theme_until` (например `10.01.2027`),
  `ny_ids` (ID подарков через запятую), `ny_order_until_ua` / `_ru` (например
  «Замовлення до 26.12 відправимо до свята»), `ny_snow` = 1 при желании,
  `gift_note` = 1 для поля подписи.
- **Готовые ответы:** `reply_1_ua` … `reply_5_ru`.
- **Источники:** `src_list` — дописать метки блогеров; ссылка блогера —
  `https://t.me/pamir_spices_bot/shop?startapp=<метка>` (латиница, цифры, `-`, `_`).
- По желанию: `home_rails_max` (3), `cart_mute_days` (30).
- **QR:** три ссылки из раздела 1 — на баннеры и вкладыш.
- **Cloudflare:** `BOT_TOKEN`, `ADMIN_CHAT_IDS`, KV, cron; **Script Properties:**
  `WORKER_URL`; **config.js:** `CATALOG_URL`.

## Отложено (решение за Исломбеком)

- Сохранение корзины и «Повідомити, коли з’явиться» остались под общей
  блокировкой с заказом.
- Ограничения частоты сообщений боту от одного человека нет (В5 из выпуска А).
- В панели на русском статусы заказов и подписи полей настроек остаются
  украинскими — они приходят с сервера.
- Фото `page` (22 шт.) — для второго фото на странице товара в Б2; у чечевицы,
  NUT-048 и тыквенных семечек `page` не использовать нигде.
- Волна Б2 — после слов «Делай волну Б2», ветка `stage9b2` от `main`.
