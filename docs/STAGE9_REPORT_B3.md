# Этап 9, выпуск Б3 — отчёт

Ветка `stage9b5-release` (объединяет `stage9b3-np-limit` и `stage9b4-errors`,
от `main` после Б2, версия 20). 20.11.2026. В `main` не слито.
Порядок выпуска: `clasp push` → ваш Deploy → «Deploy сделан» → слияние.

## 1. Что сделано

### Лимит Новой пошты («To many requests»)

**Что нашлось.** После первого отказа НП старый код продолжал слать запросы:
паузы не было, перебор страниц не останавливался. Витрина при отказе загрузки
отделений переходила на запасной поиск «запрос на каждую цифру» и повторяла
попытку каждые 30 секунд. Поиск отправителя при неудаче повторялся каждый час.
Кэш городов и отделений жил 6 часов — это потолок встроенного кэша Google.
Точную причину всплеска по коду доказать нельзя: настоящий лимит НП неизвестен.

**Что сделано.**
- **Пауза 10 минут** при «To many requests», коде 20000401501 или ответе 429:
  ни один запрос в НП не уходит ни с одного пути; то, что есть в кэше,
  продолжает отдаваться. Пауза переживает очистку кэша и снимается сама.
- **Кэш в два слоя.** Быстрый — встроенный кэш Google (до 6 часов). Долгий —
  скрытый лист «Кеш НП» в таблице: города, отделения и стоимость — 24 часа,
  данные отправителя — 7 дней. В листе только справочные данные НП: без ключа,
  телефонов и кодов отправителя. Лист создаётся сам, править его не нужно.
- **Лист пишется в фоне** раз в час, под отдельной блокировкой: заказ запись
  кэша не ждёт.
- **Поиск отправителя** при неудаче повторяется через 1, 6 и 24 часа.
- **Витрина:** расчёт стоимости — только после выбора города из подсказки и
  один раз на пару «город + ступень веса 0,5 кг»; подсказки города — от 3 букв,
  с задержкой и кэшем; список отделений — один раз на город; запасной поиск при
  ошибке НП не включается. Во время паузы поля города и отделения работают
  вручную, заказ оформляется, сообщений об ошибке покупателю нет.
- **Админу:** при паузе — текст «Нова пошта тимчасово обмежила запити…»;
  одно сообщение о лимите в сутки с числом срабатываний. Пункт меню «Етап 9Б2:
  перевірити Нову пошту» показывает паузу, состояние ежечасной задачи и размер
  кэша.

**Запросов в НП на один заказ: было → стало.** Измерено на стенде: «было» —
настоящий код выпуска Б2, запущенный в том же стенде. Город принят за 1200
отделений.

| Сценарий | Было | Стало |
|---|---|---|
| Покупатель, первый заказ в город | 6 | 6 |
| Тот же покупатель через 1 час | 0 | 0 |
| Через 7 часов | 6 | 1 |
| Через 23 часа | 6 | 1 |
| Админ: накладная (просмотр + создание) | 3 | 3 |
| Поиск отправителя за сутки при постоянной ошибке | 48 | 6 |

На первом заказе в город число запросов не изменилось. Выигрыш — после 6 часов,
в фоновых задачах и в том, что после отказа запросы прекращаются.

**Запросов витрины к серверу за одно оформление** (быстрый набор / буква в
секунду): подсказки города 2 / 6 → 1 / 4; расчёт стоимости 3 → 2; поиск
отделения при неработающем списке — запрос на каждую цифру → 0.

### Ложные ошибки «network» в сводке

**Откуда брались.** Любой сбой запроса записывался сразу, без повтора и без
проверки, видна ли страница. Когда Telegram уходит в фон, запрос рвётся — это и
попадало в сводку.

**Что сделано.**
1. Ошибка не записывается, если запрос оборван при скрытой странице, отменён
   самой витриной или упал в первые полторы секунды после возвращения. Учтены и
   собственные события Telegram о сворачивании.
2. «network» пишется только после одного автоповтора. Автоповтор — только для
   лёгких чтений (каталог, «Мої замовлення», списки панели), только после
   быстрого сбоя, вторая попытка не дольше 9 секунд. Заказ, корзина, действия
   админа, статистика и накладная сами не повторяются.
3. В сводке — число разных телефонов: «Помилки у магазині за годину: 5
   (з 3 телефонів)». Число приблизительное: очистка данных Telegram даёт «новый
   телефон».
4. Ошибки панели — отдельным блоком «Адмін-панель», в том числе фоновые запросы
   панели с экрана каталога. Только админские — сводка так и говорит.
5. Каталог: см. следующий раздел.

Ответы сервера с ошибкой на заказ и действия админа записываются всегда.

### Каталог через Cloudflare

- До этого выпуска `CATALOG_URL` был пуст: витрина в Cloudflare за каталогом не
  ходила, все «net catalog» в сводке были прямыми запросами к Apps Script.
- Теперь `webapp/config.js`: `CATALOG_URL` =
  `https://pamir-bot.pochoev2306.workers.dev/catalog`. Версии файлов `?v=28`.
- **Проверено на стенде** (адрес Worker подменён заглушкой): Worker отвечает —
  каталог из него, запросов каталога к Apps Script нет. Worker недоступен
  (обрыв, 502, мусор, пустой ответ, молчание дольше 6 секунд) — каталог из
  Apps Script, ошибки в сводке нет, одна информационная строка «Каталог через
  Cloudflare не відповів…». Недоступны оба — экран ошибки с кнопкой повтора;
  у постоянного покупателя — сохранённый каталог.
- В Worker уходит только запрос каталога, без данных покупателя. Заказ идёт в
  Apps Script, цены считает сервер.
- **Свежесть.** Worker отдаёт копию моложе 5 минут сразу; старше — сначала
  ждёт Apps Script до 4,5 секунды. Старую копию (до суток) он отдаёт, только
  если Apps Script не ответил; витрина тогда тихо перепроверяет каталог
  напрямую. После правок в панели и после «товар уже вернувся» витрина берёт
  каталог прямо из Apps Script.
- **Сброс кэша Worker.** Script Property `WORKER_URL` =
  `https://pamir-bot.pochoev2306.workers.dev` (без `/catalog` и без косой черты
  в конце). Ключ — тот же `WEBHOOK_SECRET`, что уже стоит в Apps Script и в
  Cloudflare: Apps Script шлёт его в заголовке `X-Pamir-Key`
  (`apps-script/Stage9b.gs`), Worker сравнивает со своей переменной
  (`worker/worker.js`). Нового секрета не нужно.

### Где решил сам
- Долгий кэш — в скрытом листе таблицы: встроенный кэш Google не хранит дольше
  6 часов, а таблица — единственное хранилище проекта.
- Общая пауза подсказок на витрине — только при настоящем лимите; прочие
  ошибки отключают только свой запрос.
- Подсказки по началам слов короче 4 букв в суточный кэш не пишутся.
- Сторож в Worker: копия старше 5 минут считается устаревшей — столько же жил
  каталог и без Cloudflare.
- «TypeError @ app.js:10 (екран: admin)» из моего прошлого сообщения — пример
  из тестовых данных, не настоящая ошибка магазина.

## 3. Выпуск по шагам

1. Я: `clasp push` (новый файл `Stage9b3.gs`, изменены `Code.gs`, `Stage9b.gs`,
   `Stage9b2.gs`).
2. **Вы: Deploy** → Manage deployments → карандаш у «Telegram webhook…» →
   Version: New version → Deploy. Новое развёртывание не создавать.
3. **Вы: Cloudflare** → Workers & Pages → `pamir-bot` → Edit code → вставить
   `worker/worker.js` из ветки `stage9b5-release` → Deploy. Проверка: открыть
   `https://pamir-bot.pochoev2306.workers.dev/catalog` — длинный текст с
   `"ok":true`. Убедиться, что привязано хранилище KV `PAMIR_KV`
   (`worker/README.md`, шаг 4): без него сброс кэша не доходит до покупателей.
4. **Вы: Script Properties** → `WORKER_URL` =
   `https://pamir-bot.pochoev2306.workers.dev`. `WEBHOOK_SECRET` не менять.
5. Напишите мне **«Deploy сделан»**. Я сливаю ветку в `main`, жду GitHub Pages
   и проверяю, что витрина открывается с `?v=28`.
6. **Вы:** Apps Script → Triggers — есть ли `hourlyJob`. Если нет: «PAMIR →
   Увімкнути щоденні повідомлення клієнтам». Без него кэш НП живёт 6 часов
   вместо суток и не обновляются данные отправителя.
7. **Вы:** один раз «PAMIR → Етап 9Б2: перевірити Нову пошту» — должно быть
   «Обмежень від Нової пошти зараз немає» и «Щогодинне завдання: увімкнено».
   Часто не нажимать: каждый запуск — запросы к НП.

Свойства `NP_PAUSE_UNTIL`, `NP_LIMIT_HITS`, `NP_LIMIT_ALERT_LAST`,
`NP_SENDER_RETRY`, `ERR_FB_LAST` код пишет сам — не трогать.
Не нажимать: функцию `setup()` и «Підготовка до запуску → Застосувати».

## 4. Проверки на телефоне

1. Магазин открывается, каталог виден.
2. В панели поменять цену товара → у себя видно сразу, у покупателя — через
   1–2 минуты. Вернуть цену.
3. Оформление: «Хар» → подсказка → выбрать город → список отделений; строка
   стоимости доставки появляется только после выбора города.
4. Свернуть Telegram во время загрузки и вернуться → в следующей сводке нет
   «net …».
5. Сводка: «з N телефонів», панель — отдельным блоком.
6. Через час в таблице появится скрытый лист «Кеш НП».
