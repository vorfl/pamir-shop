# Замена секретов: WEBHOOK_SECRET и BOT_TOKEN

Это только инструкция. Ничего в магазине сама по себе не меняется: вы делаете шаги руками, когда сами решите.
Значения секретов в этот файл, в чат и в проект не записываются никогда.

## 1. Как устроена цепочка (зачем важен порядок)

Сообщение от Telegram доходит до таблицы так:

```
Telegram  ->  Cloudflare Worker  ->  Apps Script  ->  таблица
```

Секрет `WEBHOOK_SECRET` живёт в трёх местах, и все три должны совпадать:

| Где | Что делает | Где в коде |
|---|---|---|
| Telegram (поле `secret_token` в `setWebhook`) | Telegram кладёт его в заголовок `X-Telegram-Bot-Api-Secret-Token` каждого запроса | ставит пункт меню «Службове: перевстановити webhook» (`apps-script/Stage9b4.gs`, `webhookReinstall_`) |
| Cloudflare, переменная `WEBHOOK_SECRET` | Worker сверяет заголовок со своим значением; не совпало: ответ 403 (`worker/worker.js`, строки 77-80). Дальше пересылает событие в Apps Script с параметром `key=` (строки 99-101) | Cloudflare → pamir-bot → Settings → Variables and secrets |
| Script Properties, свойство `WEBHOOK_SECRET` | Apps Script сверяет `key=` со своим значением (`apps-script/Code.gs`, `handleTelegramWebhook_`, строки 1684-1688) | Apps Script → Настройки проекта → Свойства скрипта |

Ещё одно использование: когда в магазине меняется каталог, Apps Script шлёт Worker запрос `/purge` с заголовком `X-Pamir-Key`
(`apps-script/Stage9b.gs`, строка 87), а Worker сверяет его со своим `WEBHOOK_SECRET` (`worker/worker.js`, строки 279-282).
Если значения разошлись, `/purge` отвечает 403. Ничего страшного: Worker сам обновляет каталог каждую минуту.

Другие значения рядом: в Cloudflare лежат `GAS_URL` (адрес Apps Script), `BOT_TOKEN` и `ADMIN_CHAT_IDS`
(только для слежения за работой: `worker/worker.js`, строки 416 и 462). `ADMIN_CHAT_IDS` есть и в Script Properties.
При замене секретов эти значения не меняются (кроме `BOT_TOKEN` в процедуре Б).

Адрес Worker для Telegram берётся из свойства `WORKER_URL` (вида `https://<имя>.workers.dev`).
`allowed_updates` пункт меню ставит такие: `message`, `callback_query`, `my_chat_member` (все типы, которые бот разбирает).
`drop_pending_updates` не ставится: ждущие сообщения не удаляются.

### Что ломается на каждом промежуточном шаге (выведено из кода)

Обозначения: T = секрет у Telegram, C = секрет в Cloudflare, P = секрет в Script Properties.

- T = C = P: всё работает.
- T = C, но C не равно P: Worker принимает событие и пересылает его, Apps Script отвечает текстом `forbidden`, но с кодом 200
  (`Code.gs`, строка 1688). Worker считает пересылку удачной (`worker.js`, строка 110), Telegram получил «ок». Событие **теряется молча**.
  Это самое опасное состояние, его нельзя допускать.
- T не равно C: Worker отвечает Telegram 403. Telegram считает доставку неудачной, держит событие у себя и повторяет.
  Сообщения не теряются, но бот молчит, пока секреты не сойдутся.

Отсюда единственный безопасный порядок: **сначала Cloudflare, потом Script Properties, потом setWebhook**.
На каждом шаге либо все три совпадают, либо Worker отвечает 403 (Telegram повторяет), но «молчаливой потери» нет.
Порядок «сначала Script Properties» (или «сначала setWebhook, потом Cloudflare») даёт состояние T = C, не равно P: события теряются без следа.

Окно, когда бот молчит: с сохранения в Cloudflare до конца шага 3. Если всё подготовить заранее, это 2-3 минуты.
Что Telegram повторяет доставку недоставленных событий, это общее поведение Telegram, но **сколько попыток и как долго он повторяет, мы не знаем**
(в документации: «разумное число попыток»). Поэтому не затягивайте окно. [НЕ ПОДТВЕРЖДЕНО: срок хранения повторов; проверяется шагом А4 ниже.]

## 2. Подготовка (один раз, до любой замены)

1. Менеджер паролей: заведите записи «WEBHOOK_SECRET (старый)» и «WEBHOOK_SECRET (новый)», «BOT_TOKEN (старый)» и «BOT_TOKEN (новый)».
   Старое значение сохраните туда **до начала** и не удаляйте, пока всё не проверено хотя бы сутки. Не в чат, не в файл проекта, не в заметки без шифрования.
2. Убедитесь, что на сервере работает выпуск с новыми пунктами меню: Apps Script → Развернуть → Управление развёртываниями → карандаш → Новая версия → Развернуть.
   (Новое развёртывание НЕ создавать: адрес изменится.) Обновите таблицу (F5): в меню PAMIR должны быть два пункта «Службове: перевстановити webhook» и «Службове: перевірити webhook».
3. В Script Properties должны быть `BOT_TOKEN`, `WEBHOOK_SECRET`, `WORKER_URL` и `USE_WEBHOOK = true`. Без `WORKER_URL` или `USE_WEBHOOK` пункт меню откажется работать и ничего не сделает.
4. Нажмите **PAMIR → Службове: перевірити webhook**. Ожидаемо: «Webhook встановлено: так», хост совпадает с WORKER_URL, ошибок нет. Это ваша точка отсчёта. Если здесь уже что-то не так, замену не начинайте.
5. Откройте заранее три вкладки: Cloudflare (Variables and secrets у pamir-bot), Apps Script (Свойства скрипта), таблица PAMIR.

## Процедура А. Замена WEBHOOK_SECRET

### А0. Придумать новое значение

Нужно 48 знаков из набора A-Z a-z 0-9 _ - (так требует Telegram: 1-256 знаков; пункт меню требует не короче 32).
Откройте PowerShell (меню Пуск → PowerShell) и вставьте одну строку:

```
$b = New-Object byte[] 36; (New-Object System.Security.Cryptography.RNGCryptoServiceProvider).GetBytes($b); [Convert]::ToBase64String($b).Replace('+','-').Replace('/','_')
```

Значение появится на экране. Скопируйте его сразу в менеджер паролей («WEBHOOK_SECRET (новый)») и закройте окно. Программы ставить не нужно, в файл ничего не пишется.

### А1. Cloudflare: сохранить новое значение (окно открывается)

Cloudflare → Workers & Pages → pamir-bot → Settings → Variables and secrets → `WEBHOOK_SECRET` → Edit → вставить новое значение → Save and deploy.
[ЗАГЛУШКА: названия кнопок в Cloudflare могут отличаться, ориентируйтесь на экран.]

Проверка: откройте адрес Worker в браузере. Должна быть надпись «PAMIR bot worker: ok». Откат: вставить обратно старое значение и сохранить. Тогда все три снова совпадают.

### А2. Script Properties: то же новое значение

Apps Script → Настройки проекта (шестерёнка) → Свойства скрипта → Изменить → `WEBHOOK_SECRET` = новое значение → Сохранить. Без пробелов и переводов строки в конце.

Проверка: значение сохранилось (откройте список ещё раз, длина та же). Откат: в Cloudflare и здесь вернуть старое значение (сначала Cloudflare, потом здесь).

### А3. Таблица: перевстановить webhook (окно закрывается)

PAMIR → **Службове: перевстановити webhook** → прочитайте окно (оно называет только адрес Worker, секрет не показывает) → «Да».

Ожидаемо в итоговом окне: «setWebhook виконано», «Webhook встановлено: так», хост совпадает с WORKER_URL, `pending_update_count` может быть больше нуля (накопилось, пока был 403) и должен упасть до 0 за 1-2 минуты.
Если окно говорит «закороткий» или «недозволені знаки», значение не подходит по формату; вернитесь к А0.
Если «setWebhook НЕ вдалося»: проверьте значения, повторите. Пока не удалось, бот молчит; при затяжке откат (ниже).

### А4. Проверки

1. Через минуту: PAMIR → **Службове: перевірити webhook**: «Webhook встановлено: так», `pending_update_count` = 0, свежей ошибки нет.
2. Напишите боту `/start` со своего телефона: бот отвечает.
3. Если во время окна вы писали боту (рекомендуется отправить `/start` сразу после А1): ответ должен прийти уже после А3. Это и есть проверка, что события не потерялись.
4. В чате админов нажмите кнопку статуса у любого заказа: статус меняется.
5. PAMIR → **Оновити каталог у магазині зараз**: окно «Каталог оновлено». В Cloudflare → pamir-bot → Logs виден запрос `POST /purge` без 403.

### А5. Откат (на любом шаге)

Правило то же, что и при замене: сначала Cloudflare, потом Script Properties, потом таблица.
1. Cloudflare: вернуть старое значение, сохранить.
2. Script Properties: вернуть старое значение.
3. PAMIR → Службове: перевстановити webhook (Telegram получит старый секрет). Проверки А4.

Когда всё проверено хотя бы сутки, старое значение в менеджере паролей можно пометить как «использован, недействителен».

## Процедура Б. Замена BOT_TOKEN

Важно: **вернуть старый токен нельзя**. Как только BotFather выдал новый, старый перестаёт работать сразу. Отката нет, есть только «исправить вперёд».
Пока новый токен не внесён в Script Properties, бот не может отвечать, а заказы из магазина не проходят проверку подписи Telegram.
Поэтому: вкладки открыть заранее, новый токен копировать сразу, шаги делать подряд.

### Б1. BotFather: новый токен

В Telegram откройте @BotFather → `/revoke` → выберите бота @pamir_spices_bot → BotFather пришлёт новый токен.
(Если вы пользуетесь меню бота в приложении BotFather: «API Token» → «Revoke current token».) [ЗАГЛУШКА: точные названия кнопок проверьте на экране; команда `/token` только показывает текущий токен и ничего не меняет.]
Скопируйте новый токен сразу в менеджер паролей («BOT_TOKEN (новый)»). В чат его не пересылайте.

### Б2. Script Properties

Apps Script → Свойства скрипта → `BOT_TOKEN` = новый токен → Сохранить.

Проверка: PAMIR → **Службове: перевірити webhook**. Если токен принят, придёт статус webhook. Если «Unauthorized» или «не вдалося отримати стан»: токен вставлен неверно (лишний пробел, не весь токен). Исправьте и повторите.
Если «Webhook встановлено: ні»: webhook слетел вместе с токеном (поведение Telegram при замене токена [НЕ ПОДТВЕРЖДЕНО]), переходите к Б4.

### Б3. Cloudflare (слежение)

Cloudflare → pamir-bot → Variables and secrets → `BOT_TOKEN` = новый токен → Save and deploy. Эта переменная нужна только для сообщений админам о сбоях: бот и магазин без неё работают.

### Б4. Таблица: перевстановить webhook

PAMIR → Службове: перевстановити webhook. Секрет при этом не меняется (берётся из Script Properties), это просто страховка.

### Б5. Проверки

1. `/start` боту: ответ приходит.
2. В магазине оформите тестовый заказ как покупатель (откройте магазин заново, закрыв старые окна: старая сессия подписана прежним токеном): заказ проходит, админам приходит сообщение с кнопками.
3. PAMIR → **Оновити опис бота**: четыре строки «готово».
4. PAMIR → Службове: перевірити webhook: «так», ошибок нет.

### Если после замены бот молчит

1. «Перевірити webhook»: нет webhook, `last_error_message` с 401/403: токен или секрет.
2. Токен: в Script Properties нет пробелов и переводов строки, вставлен целиком.
3. Секрет: 403 в Cloudflare → Logs значит, что секреты не совпали; повторите процедуру А или откат А5.
4. Apps Script → Выполнения: есть ли ошибки `doPost`.
5. Совсем не получается получить рабочий токен: ещё раз `/revoke` у BotFather (выдаст следующий новый токен) и повторить Б2-Б5.

## Чего НЕ делать

- Не запускать `setup()` и `startPolling()`: опрос удаляет webhook, и бот замолчит.
- Не вызывать `deleteWebhook` и не открывать в браузере ссылки `api.telegram.org/bot<токен>/...`: токен остаётся в истории браузера.
- Не публиковать значения секретов и токена: ни в чате, ни в GitHub, ни в скриншотах (пункты меню их не показывают, но окна Cloudflare и Свойств скрипта показывают).
- Не создавать новое развёртывание Apps Script: адрес изменится, и Worker начнёт ходить по старому. Только «Новая версия» у существующего.
- Не менять секрет «в одном месте»: Cloudflare, Script Properties и Telegram всегда в порядке А1, А2, А3.

## Что не проверено

- Настоящий Telegram: пункт меню проверен только на стенде с имитацией ответов Telegram (вызываются только `setWebhook` и `getWebhookInfo`; секреты в окнах и журнале не появляются).
- Сколько времени и сколько раз Telegram повторяет доставку после ответов 403: в документации нет точных цифр.
- Сохраняется ли webhook после смены токена: проверяется шагом Б2.
- Названия кнопок в Cloudflare, Apps Script и BotFather могут отличаться от описанных.
