Откат: Manage deployments → карандаш → записанная версия → Deploy; на GitHub — Revert у слитого PR.

## Как это работает

### В1. «Як їсти» и рецепты
- «Як їсти» — 1–3 строки в колонке товара или в карточке товара в панели. Пусто — блока нет.
- Рецепт — строка в листе «Рецепти». Показывается, когда в «Показувати» стоит `так`. В «Товари» — ID ингредиентов через запятую.
- Фото рецепта: ссылка `https://…` видна на витрине и в рассылке; код фото от бота (`file_id`) годится только для рассылки — на витрине такого фото не будет.
- На главной блок «Рецепти», в карточке товара — «Рецепти з цим товаром».
- «Додати інгредієнти в кошик» кладёт только товары в наличии (весовые — самой маленькой доступной фасовкой, по одной штуке). Про остальные — «Зараз немає в наявності: …». Повторное нажатие второй раз не добавляет.
- Панель → Розсилка → «Шаблон «Рецепт»»: подставляет текст, фото и кнопку «Відкрити рецепт».
- Черновики для урюка — в `docs/RECIPES_DRAFT_URYUK.md`. Это пример: в таблицу они не вносились, тексты утверждаете вы.

### В2. Квиз
- В колонке «Теги» товара — через запятую: `до чаю`, `перекус`, `подарунок`, `солодке`, `солоне`, `для плову`, `для випічки`.
- На главной кнопка «Підібрати смаколики». Три вопроса: для чего, сладкое или солёное, бюджет на одну позицию. В вопросах только те варианты, для которых есть товары в наличии.
- Результат — до 6 товаров в наличии. Нет совпадений — популярные товары по настоящим заказам.
- Нет ни одного товара в наличии с тегами — кнопки нет.

### В3. «Пригости друга»
- **Выключено по умолчанию.** Включается в панели → Налаштування: `referral_on` = `1` и текст пробника в `referral_gift_ua` (например «50 г кураги»). Пока одно из двух не задано, функции нет нигде и ссылки не выдаются.
- У клиента в профиле блок «Пригости друга» и личная ссылка `t.me/pamir_spices_bot/shop?startapp=ref_<id>`.
- Новый клиент по ссылке получает пробник к первому заказу от `referral_min_order`. В заказе у админа строка «Пробник за запрошенням друга: …».
- Пригласивший получает такой же пробник к своему следующему заказу — по одному пробнику на заказ за каждого друга.
- Один новый клиент засчитывается один раз. Себя пригласить нельзя. У кого уже были заказы — тот не «новый». Тестовые заказы не считаются.
- Учёт — лист «Запрошення», записи в «Журнал». Сумма заказа не меняется, денежных бонусов нет.

## Часовой пояс (раздел 4а): что выяснил и почему не менял

Пояс проекта Apps Script сейчас `Europe/Berlin`. **Я его не менял**, потому что на стенде нельзя проверить, какое написание примет живой Apps Script (`Europe/Kiev` или `Europe/Kyiv`) и как поведут себя уже созданные таймеры. По заданию при неясном риске — только описать.

Что зависит от пояса проекта:

| Что | Зависит? | Пояснение |
|---|---|---|
| Ежедневный таймер `dailyJob` («около 11:00») | **да** | Час задан в поясе проекта: сейчас это 11:00 по Берлину = 12:00 по Киеву. После перевода станет 11:00 по Киеву, на час раньше |
| Ежечасный таймер, таймер рассылки (раз в 10 минут) | нет | работают по интервалу |
| Время отложенной рассылки | нет | считается явно по Киеву; тесты на оба перевода часов есть |
| Даты в «Замовлення», «Журнал», «Події», «Клієнти», «Розсилки» | нет | в ячейку пишется момент времени; как он показан — решает пояс **таблицы** (Файл → Настройки), а не проекта |
| Время в панели, в сообщениях бота, статистика по дням, «сегодня» | нет | в коде везде явно `Europe/Kiev` |
| «Акція до», «Свіжа поставка» | нет | дата текстом; дата-ячейка читается по поясу таблицы |
| «Не заказывали 30+ дней», лимит рассылок, напоминания | нет | считаются разницей во времени |

Тесты: заказ в 23:50 и в 00:10 по Киеву попадают в разные дни; последнее воскресенье марта и октября; в коде нет обращений к поясу проекта.

Если будете переводить (отдельной задачей):
1. В `apps-script/appsscript.json` заменить `Europe/Berlin` на `Europe/Kiev`, `clasp push`, New version.
2. Старые записи в таблице **не сдвинутся**: меняется только то, когда срабатывает ежедневный таймер.
3. Меню PAMIR → «Увімкнути щоденні повідомлення клієнтам» — пересоздать таймеры.
4. На следующий день проверить в Apps Script → «Выполнения», что `dailyJob` сработал около 11:00 по Киеву.
5. Отдельно посмотреть пояс самой таблицы (Файл → Настройки → Часовой пояс): от него зависит, как показано время в ячейках.

## Решения, принятые самостоятельно

| Вопрос | Решение и причина |
|---|---|
| Рецепты редактируются в таблице, а не в панели | В задании панели для рецептов нет, кроме шаблона рассылки; длинные тексты удобнее писать в таблице |
| Фото-код (`file_id`) на витрине | Не показывается: браузер такой код открыть не может. Наружу уходит только отметка, что код есть |
| «Додати інгредієнти»: сколько класть | По одной самой маленькой доступной фасовке; количество клиент меняет в корзине |
| Квиз: что считать бюджетом | Цена самой маленькой фасовки товара — столько реально можно потратить на позицию |
| Квиз: варианты ответов | Только те теги, для которых есть товары в наличии; иначе вопрос вёл бы в пустоту |
| Где кнопка квиза | На главной, над строкой «для бізнесу» |
| Пригласившему — минимальная сумма | Не требуется: в задании она указана только для нового клиента |
| Несколько приглашённых друзей | Один пробник на один заказ пригласившего, остальные — к следующим заказам |
| Кто «новый клиент» | Тот, у кого не было ни одного не тестового заказа, включая отменённые |
| Откуда сервер знает пригласившего | Витрина запоминает ссылку до первого заказа и передаёт id; сервер проверяет всё остальное сам |
| Черновики урюка | Только файл в `docs/`; пропорции плова не выдумывал |
| Часовой пояс | Не менял: риск на живом проекте со стенда не проверить |
