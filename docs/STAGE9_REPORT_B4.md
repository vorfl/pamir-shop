## 1. Что сделано

### п.1 Скорость сборки каталога, п.2 очистка тестовых данных, п.4 замена ключей
Сделаны до выключения (коммиты `6ac986c`, `799b104`), в этом отчёте не
менялись, кроме одного: витринная часть очистки по `client_data_version`.

**Очистка данных покупателя на телефоне (`shop.cdv`).** Когда вы меняете
настройку `client_data_version`, витрина один раз стирает у покупателя корзину,
«Обране», «Ви дивились», поиски, форму оформления. Язык, тема и админские
настройки не трогаются.
Приёмка нашла ошибку: метка «уже очищено» хранилась только на устройстве,
поэтому покупатель, зашедший с нового телефона или с компьютера, стёр бы свою
настоящую корзину в облаке Telegram. Исправлено: метка хранится и в облаке
Telegram, очистка — один раз на покупателя.
Известное ограничение: если в момент очистки облако Telegram ответило ошибкой,
стирается только телефон, облако не трогается (вслепую не стираем). У такого
человека тестовая корзина может вернуться из облака при следующем открытии.
Касается только тех, кто пользовался магазином до очистки.

### п.3 Строка о комиссии наложенного платежа
В оформлении под способами оплаты при выборе «Накладений платіж»:
«Нова пошта бере за накладений платіж 20 ₴ + 2 % від суми.» Если в этом заказе
доступна оплата на счёт ФОП, добавляется «Оплата на рахунок ФОП — без цієї
комісії.» Это только текст: сумма заказа и тело заказа не меняются.

**[ЗАГЛУШКА: цифры «20 ₴ + 2 %» не сверены.]** В репозитории и документах их
источника нет, они появились в прерванной сессии. См. «Вопросы к вам».

### п.5 Справочник Новой пошты через Worker
- Worker (коммит `41fdc50`): сам раз в сутки маленькими шагами загружает города
  и отделения НП в хранилище KV и отдаёт подсказки по адресам `/np/cities`,
  `/np/warehouses`; состояние — `/np/status`.
- Витрина (сделано после выключения): подсказки города и список отделений
  берутся из Worker (`NP_URL` в `webapp/config.js`). Если Worker не ответил за
  4 секунды, ответил ошибкой или справочник ещё не загружен — витрина сама идёт
  прежним путём через Apps Script и 10 минут Worker не трогает. Покупатель
  разницы не видит.
- Пока справочник в Worker исправен, подсказки работают, даже когда Новая пошта
  ограничила Apps Script (пауза 10 минут из Б3).
- В Worker уходит только набранный текст или код города, без данных покупателя.
- Стоимость доставки, накладные и статусы по-прежнему делает Apps Script.
- Работает и без `NP_URL`, и со старым Worker, и со старым бэкендом.

### п.6 Скорость оформления заказа
Новый файл `apps-script/Stage9b5.gs`.
- **Всегда:** сообщения админам уходят одной пачкой, а не по одному; лишнее
  чтение заголовков листа и второй сброс таблицы убраны.
- **По желанию — «Швидке оформлення замовлень»** (пункт меню PAMIR, по
  умолчанию выключено). Заказ записывается в таблицу, покупатель сразу видит
  «Замовлення прийнято», а сообщения админам и покупателю отправляет фоновая
  задача раз в минуту.
  - Пометка «надіслати» лежит в самой строке заказа, поэтому заказ без
    сообщения остаться не может.
  - Каждому получателю — не больше одного сообщения.
  - Telegram недоступен: 5 попыток раз в минуту, затем раз в 10 минут до
    24 часов. После 5 неудач — тревога владельцу и админам с ролью «Адмін»
    (только номер заказа); тревога повторяется, пока не дойдёт.
  - Фоновая задача остановилась — заказы снова шлют сообщения сами.
- **Замер** (Script Property `PERF_LOG` = 1): одна строка на заказ в журнале,
  только названия этапов и миллисекунды.

На один заказ (3 админа и покупатель), измерено на стенде:

| Режим | Запросов к Telegram | Обращений в сеть | Записей в лист |
|---|---|---|---|
| до Б4 | 4 | 4 | 4 |
| сейчас, обычный | 4 | 2 | 4 |
| быстрое оформление, сам заказ | 0 | 0 | 1 |
| быстрое оформление, фоновая задача | 4 | 2 | 6 |

Секунды на стенде не измеряются: настоящий выигрыш покажет `PERF_LOG` на живой
таблице.

**Ошибка, найденная в WIP и исправленная:** без файла `Stage9b5.gs` заказ
записывался, но сообщения не уходили. Добавлена запасная отправка.

## 3. Выпуск по шагам

Витрина, бэкенд и Worker совместимы в любом порядке: без нового Worker или
ключа подсказки идут старым путём.

1. Я (после вашего «да»): `clasp push`. Новые файлы `Stage9b4.gs`,
   `Stage9b4clean.gs`, `Stage9b5.gs`; изменены `Code.gs`, `Stage9b.gs`.
2. **Вы: Deploy** → Manage deployments → карандаш у «Telegram webhook…» →
   Version: New version → Deploy. Новое развёртывание не создавать.
3. **Вы: Cloudflare, код.** dash.cloudflare.com → Workers & Pages → `pamir-bot`
   → Edit code → Ctrl+A → вставить `worker/worker.js` из ветки `stage9b6` →
   Deploy.
4. **Вы: Cloudflare, секрет.** `pamir-bot` → Settings → Variables and secrets →
   Add. Type: **Secret**. Variable name: строго `NP_API_KEY`. Value: ключ API
   Новой пошты — тот же, что в Script Properties таблицы (`NP_API_KEY`).
   Вводите сами, в чат не присылайте. Deploy.
   [ЗАГЛУШКА: названия пунктов панели Cloudflare не сверены.]
5. **Вы: Cloudflare, расписание.** `pamir-bot` → Settings → Triggers → Cron
   Triggers. Должна быть одна строка `*/5 * * * *`. Есть — ничего не делать.
   Нет — Add → вписать `*/5 * * * *` → сохранить. Второго расписания не нужно.
6. **Вы: Cloudflare, хранилище.** Settings → Bindings: есть ли KV с именем
   `PAMIR_KV` (привязано в Б3). Без него справочник не работает.
7. **Вы: проверка.** Открыть
   `https://pamir-bot.pochoev2306.workers.dev/np/status`. Должно быть
   `"key":true` и `"kv":true`; через 5–10 минут `percent` начинает расти.
   Первая загрузка — по оценке 9–10 часов (не замерено). Пока она идёт, всё
   работает через Apps Script.
8. Напишите мне **«Deploy сделан»**. Я сливаю ветку в `main`, жду GitHub Pages
   и проверяю, что витрина открывается с `?v=29`.
9. **Вы, перед открытием магазина:** «PAMIR → Очистити тестові дані перед
   відкриттям» и настройка `client_data_version` (любое новое значение,
   например дата) — по подсказкам пункта меню.
10. **Вы, по желанию и не в первый день:** «PAMIR → Швидке оформлення
    замовлень: увімкнути». Сделать пробный заказ: «Замовлення прийнято» сразу,
    сообщения — в течение минуты. Выключить: «…: вимкнути» (очередь
    досылается сразу).

Новые Script Properties вручную добавлять не нужно: `ORDER_QUEUE` ставит пункт
меню. `PERF_LOG` = 1 — только на время замера, потом удалить.
Не нажимать: функцию `setup()` и «Підготовка до запуску → Застосувати».

Если в `/np/status` что-то не так — `worker/README.md`, раздел «Если что-то
пошло не так».
